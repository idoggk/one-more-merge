# Unit style test: STYLE 4 "vector icon"

Generated by `node tools/render-unit-style-test.mjs` (SVG strings -> PNG with sharp, already a devDependency; nothing paid, nothing wired into `src/`).

## What is here
- `svg/<family>_r<rank>.svg` - source vectors (256x256 viewBox), 9 files.
- `png/<family>_r<rank>_128.png` and `_256.png` - transparent PNGs.
- `sheet_dark.png`, `sheet_light.png` - contact sheets (rows = families, columns = rank 1, 4, 8).
- `sheet_48_dark.png`, `sheet_48_light.png` - same sheets with each unit at 48 px (phone size).
- `sheet_grey_*.png`, `sheet_48_grey_*.png` - greyscale versions at 256 and 48 px.

## Families
The first three confusion-pair families in `UNIT_ROSTER_AUDIT.md` section 3 are Bell vs Horn, then Coil (Coil vs Capacitor vs Dynamo): **Bell** (gold dome), **Horn** (orange cone), **Coil** (cyan plus). Bell and Horn have the same job turned 90 degrees, so the test is whether silhouette + colour alone separates them.

## Style rules used
- One silhouette per family (dome / tall flared cone / plus), flat family colour that never changes with rank.
- Thick dark outline (11 units on a 256 grid), one white highlight shape, one dark shadow shape (both clipped to the body), at most 3 detail shapes.
- Rank = size step (scale 0.55 / 0.70 / 0.86) + pips (1 / 4 / 8) + glow ring (faint, medium, bright with halo). Identical for every family and defined once in `unitSvg()`.

## Honest observations
- Silhouettes survive 48 px and greyscale; Bell vs Horn is clearly separable by shape alone.
- Rank 1 vs 4 vs 8 reads from size, pips and ring, not colour.
- The glow ring is cream: weak on the light sheet. A real build needs a ring colour that works on both (e.g. a dark inner stroke) or backgrounds that are always tile-dark.
- At rank 8 the 8 pips (two rows) start to look like noise at 48 px; a "star" or numeral badge may beat counting dots above about 5.
- Bell clapper and Horn mouthpiece are the only "details"; the Horn light band is a 4th shape, so it is at the limit.

## Extending to all 9 families
Core families from the audit: Gun(Cannon), Rocket, Arc, Cross(Coil), Row(Bell), Diagonal(Fuse Box), Boost(Battery), Fan, Pair(Magnet).
- Effort: about 0.5 to 1 day per family for a first silhouette and review, then the pipeline is free: add one entry to `FAMILIES` (body path, highlight, shadow, details) and run the script for all 8 ranks. Roughly 3 to 4 days for the 9, plus review iterations. 72 images regenerate in seconds, so palette or outline changes are one-line edits.
- Constraints: hand-written paths need a visual check each (no editor); keep one silhouette class per family (dome, cone, plus, tube, X, cell, blades, U, prongs) so no two share an outline; all 9 colours must differ in luminance as well as hue for greyscale; rank 1-8 must stay legible, so rank 5-8 need a shared extra cue (crown or star badge) not just bigger size; the glow ring and pips live in one shared function so every family stays consistent.
- Unity: SVG imports through the Unity Vector Graphics package (or export the same PNGs at 512 and use sprites). The script's shape lists map 1:1 to layered sprites (body, highlight, shadow, details), which lets Unity tint the family colour, tween the pips/glow and squash-and-stretch the body without extra art. Animation cost is low because parts are separate shapes; mesh-deform animation would need the Unity vector package or a skinned sprite pass.
- Limit: this style cannot carry painted texture or lighting, so it will look different from the existing painted art (owner choice, that is the point of the test).
